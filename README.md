# 钟乳石断面摄影测量复核台

洞穴保护组每月为钟乳石断面拍摄标准照。本系统把“只存链接”升级为摄影测量复核台：
登记标尺编号与像素/毫米换算，自动判定增长是否成立，并由另一位测量员双人复核。

## 启动

```bash
npm install
npm start
```

默认地址：http://localhost:3912 ；数据保存在 `data/db.json`。

## 规则、存储、页面三层分离

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 规则层 | `rules.js` | 全部业务阈值与判定（纯函数，无 HTTP/文件依赖），前后端共用同一份：浏览器经 `/rules.js` 加载，服务端 `require` |
| 存储/HTTP 层 | `server.js` | 读写 `data/db.json`、通用集合接口、复核工作流专用端点；所有判定都委托 `rules.js` |
| 配置/页面层 | `project.config.js`、`public/` | 集合字段、状态、工作流按钮的声明式配置；页面只读规则结果，不自行下结论 |

## 业务规则

1. **标尺独占**：登记复核时选择标尺编号。同一标尺在某个样点的复核链条完成前，不能给其他样点使用；同一样点可连续使用。标尺台账实时显示“空闲可领用 / 占用中（样点）”。
2. **像素与毫米换算**：录入标尺读数（mm、px）与断面像素长度，按 `mm/px` 换算断面长度（mm）。
3. **待重拍**：标准照链接缺失，或本次换算相对标尺标定值的偏差绝对值 **超过 1%**，一律只进「待重拍」，不进入确认环节。
4. **双人确认**：合格记录进入「待确认」，须由**另一位测量员**（不同于拍摄人）签名确认；要求**连续两次增长同向**且两次增长量差值 **不超过 0.2 mm**。该样点首次通过时锚点为基准长度，不设同向门槛。
5. **增长锚点**：默认取该样点最近一次「已通过」复核；无则回退到样点基准长度。
6. **失效重算**：
   - **样点基准更正**：该样点全部「已通过」复核变「已失效」，待确认记录按新基准立即重算；
   - **历史拍摄更正**：被更正的已通过记录回到待确认重判，其后的已通过复核联动失效，待确认记录自动重算锚点与增长。

每条记录都带完整履历（登记、重拍、重算、失效、双人确认等时间戳留痕）。

## 数据集合

- `sites` 样点档案（含基准断面长度 baselineMm）
- `rulers` 标尺台账（标定 mm / px）
- `reviews` 复核记录（照片、读数、换算偏差、断面长度、增长、锚点、状态、确认人、履历）

状态：`待重拍` / `待确认` / `已通过` / `已失效`。

## 工作流端点

- `POST /api/reviews` 登记月度复核（自动判定待重拍 / 待确认，并校验标尺占用）
- `POST /api/reviews/reshoot/:id` 登记重拍（可换标尺/换人/重读像素）
- `POST /api/reviews/confirm/:id` 另一位测量员确认（双人 + 同向 + 0.2mm）
- `POST /api/reviews/correct/:id` 历史拍摄更正（级联失效与重算）
- `POST /api/sites/baseline/:id` 样点基准更正（相关增长失效重算）

样点与复核记录禁止直接 `PATCH/DELETE`，必须走上述工作流，保证履历可追溯。
